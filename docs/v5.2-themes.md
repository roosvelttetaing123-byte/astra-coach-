# Astra Coach v5.2 — three themes and Auto

Roles: one architect agent designed this and reviews the result; two implementer agents write the code. This file is the contract between them.

## Why

The user found v5.1's flat black-and-grey UI "dark and depressing". Mockups of three directions were made on the real screens, and the user's answer was: all three, selectable, plus an automatic mode that changes with the time of day.

## Themes

`<html data-theme="…">` always holds the **resolved** theme: `daylight`, `energy` or `glow`. "Auto" is a setting, never a DOM value. The old flat-black palette goes away; Night Glow is the dark theme now.

| | Daylight | Energy | Night Glow |
|---|---|---|---|
| Mood | Bright, clean, Apple Fitness/Health light | Warm, sporty, bold brand colour | Rich indigo dark with colour light |
| Page | `#F2F2F7` | `#FBF7F2` (warm off-white) | `#0B0F24` plus two soft radial glows (violet top-right, cyan left) |
| Cards | `#FFFFFF`, soft shadow `0 1px 2px` + `0 8px 24px` at ~6 % | `#FFFFFF`, warm shadow | `rgba(255,255,255,.06)` + 1 px `rgba(255,255,255,.08)` border; **no backdrop-filter on cards** |
| Text / muted | `#0B0B0F` / `#5E5E66` | `#1A120B` / `#6E6258` | `#F4F5FF` / `#A9B0D6` |
| Accent (links, icons, focus) | iOS blue, darkened for text where needed | coral `#E8461E`-ish, darkened for text | periwinkle `#7C9CFF` |
| Filled buttons | `#0A6FD8`, white text | ink `#1A120B`, white text | indigo→violet `#5B5BF0`→`#8B45F0`, white text |
| Selected pill | ink `#0B0B0F`, white text | coral→magenta gradient, white text | indigo→violet gradient, white text |
| Today hero | gradient by workout: rest teal, upper blue→indigo, lower orange→pink, light day green→teal | one brand gradient coral→red→magenta for every workout | gradient by workout, deeper and more saturated |
| Hero button | white, ink text | ink, white text | white, deep indigo text |
| Tab bar | white glass `rgba(255,255,255,.82)` + blur + shadow | warm white glass | `rgba(20,24,56,.72)` + blur |
| Status bar / `theme-color` | `#F2F2F7` | `#FBF7F2` | `#0B0F24` |
| `color-scheme` | light | light | dark |

The reference mockups (CSS overrides on the live app) are in the scratchpad: `concepts/a-daylight.css`, `b-energy.css`, `c-glow.css`. They are a starting point for colour, not finished code.

### Rules for every theme

- **WCAG AA everywhere:** body text 4.5:1, large text (≥ 24 px, or ≥ 18.66 px bold) 3:1, against the actual colour behind it. On gradients, measure at the text's position. Make the end of the gradient where text sits deep enough, and keep the bright end away from text (e.g. bright top-right → deep bottom-left).
- **No leftovers from the dark design:** no white text on light surfaces (e.g. "Mark day as fully logged"), no `rgba(255,255,255,…)` borders on light cards, no navy SVG fills. Every colour comes from a theme token.
- **The hero art (`.today-art`, the user's approved portrait)** stays, blended into the gradient (`mix-blend-mode: soft-light` or `luminosity` at reduced opacity) so it adds texture without gloom. Text contrast rules still apply.
- **Performance:** `backdrop-filter` only on the tab bar and the sheet backdrop. Night Glow's glows are a `position: fixed` pseudo-element behind the app, not `background-attachment: fixed` (iOS ignores it).
- **Theme change animates** (≈ 400 ms crossfade of background, colour and border colours) only when `<html>` has class `theme-anim`, which app.js adds after first paint. Off under `prefers-reduced-motion`.
- Type, spacing, radii, tap targets and the v5.1 metrics stay as they are (9 sizes, weights 400–700, nothing under 11 px, targets ≥ 44 px).

## Auto: time of day

| Local time | Theme |
|---|---|
| 05:00–11:59 | Daylight |
| 12:00–18:59 | Energy |
| 19:00–04:59 | Night Glow |

Auto is the default. It re-evaluates on load, on `visibilitychange` to visible, and with a timer set for the next boundary, so an open app switches at 12:00 and 19:00 with the crossfade.

## Part A — behaviour (`app.js`, `index.html`, `sw.js`, `manifest.webmanifest`, `README.md`). Agent A.

- **A1 Setting.** `S.profile.theme` ∈ `auto | daylight | energy | glow`, default `auto`. `migrate()` fills it, and `validateBackup()` accepts these four values and turns anything else into `auto`, so v5.1 backups still restore. Mirror the setting to localStorage key `astra.theme` (plain string) whenever it changes and at boot.
- **A2 Resolution.** Add `themeFor(mode, date)`, the table above. `applyTheme()` sets `data-theme`, updates `<meta name="theme-color">` to the theme's status colour, and schedules the next boundary when the mode is Auto.
- **A3 No flash.** Add a tiny inline `<script>` in `index.html` `<head>`, before the stylesheet link. It reads `astra.theme`, resolves the theme with the same schedule (comment that it must match `themeFor`), and sets `data-theme` and `theme-color` before first paint. Wrap it in try/catch with a `daylight` fallback.
- **A4 Head meta.**
  - `apple-mobile-web-app-status-bar-style` becomes `default`, because `black-translucent` forces white status text that would vanish on light themes.
  - `color-scheme` becomes `light dark`.
  - Manifest `theme_color` and `background_color` become `#F2F2F7`.
- **A5 Appearance control.**
  - Add an "Appearance" row near the top of More, showing e.g. "Auto · Energy now". It opens an Appearance sheet with four large radio cards (Auto, Daylight, Energy, Night Glow), each with a small swatch preview.
  - The Auto card states the schedule ("Daylight 5 am–noon · Energy noon–7 pm · Night Glow 7 pm–5 am").
  - Selecting a card applies and saves immediately (live preview), with no Save button.
  - Use existing helpers (`modal`, `heading`, `btn`), `esc()`, and ≥ 44 px targets.
- **A6 SVG colours to classes.** Remove colour presentation attributes and add classes; Agent B styles them:
  - settings icon knobs `fill="#142338"` → `class="knob"`;
  - Progress weight chart grid `stroke="#46617a"` → `class="chart-grid"`, raw line `stroke="#50baff"` → `class="chart-raw"`, trend `stroke="#0091FF"` → `class="chart-trend"`, points `fill="#70e9c1"` → `class="chart-pt"`.
  - Keep geometry and opacity attributes.
  - No other hard-coded colours may remain in app.js markup.
- **A7 `theme-anim`.** Add class `theme-anim` to `<html>` about 300 ms after first render.
- **A8 Version 5.2.0.** Bump `VERSION`, every `?v=`, the `sw.js` shell list, the cache name `astra-coach-shell-5.2.0` and the sidebar label. Add a README "New in v5.2" section (themes, Auto schedule, the iOS focus-ring fix).

## Part B — themes (`styles.css` only). Agent B.

- **B1 Theme tokens.** One token block per `[data-theme]`. Rename the accent tokens semantically (`--accent`, `--accent-fill`, `--accent-fill-press`, `--accent-text`, plus pill, hero, tab, chart, success and warn tokens as needed) and update every use. `:root` without `data-theme` falls back to Daylight.
- **B2 Sweep every component in every theme:**
  - pages: Today, Train, Nutrition, Progress, More, desktop sidebar;
  - sheets: exercise (set rows, done state, rest timer, hurt chips, plate line), check-in choices, finish and celebration, review, food form, weigh-in, endurance, settings, plan, phase, swap, safety, sources, the new Appearance sheet;
  - small parts: toasts, callouts (info and warn), chips, inputs and placeholders, switches, segmented controls, details/summary, food tiles, Recent strip, macro bars, calorie ring, volume bars, L/R balance, stat boxes, history rows, storage alert, skip link.
- **B3 Charts and SVG:**
  - Today's `.trend-line`, `.trend-fill`, `.trend-dot` and `.trend-goal`;
  - Agent A's new `.knob`, `.chart-grid`, `.chart-raw`, `.chart-trend` and `.chart-pt` (until A lands, test by adding those classes in a page script);
  - icon tiles `.sq.*`.
- **B4 Motion.** The `theme-anim` crossfade, in the single reduced-motion block.
- **B5 Focus rule.** Change the iOS focus-ring rule to `:where([tabindex="-1"],dialog):focus{outline:none}`. It keeps zero extra specificity, so a future `<button tabindex="-1">` keeps its keyboard ring, and author styles still beat Safari's UA ring.

## Acceptance

- `node --test` 86/86 and `node --check` on every JS file.
- For each theme, with the seeded fixture and a fresh profile: no console errors and no `NaN`/`undefined` text; screenshots of every tab and the main sheets reviewed; a contrast scan passes AA, with false positives named.
- The type and tap-target metrics are unchanged.
- Auto flips at 05:00, 12:00 and 19:00, using Playwright `page.clock`. The setting survives reload, and backups round-trip, including v5.1 backups with no `theme`.
- Don't commit. The architect reviews, commits and ships.

## Outcome

Shipped as specified. 106 colour tokens are registered with `@property`, so a theme change crossfades every colour, gradients included, over 400 ms. The three themes are scoped by `[data-theme]` (Daylight is the fallback), and there are no colour literals in component rules. The Appearance swatches render with the real theme tokens.

Checks: `node --test` 86/86. The contrast scan measured the real pixels behind every text run on every tab and ~25 sheets and states, in seeded and fresh profiles: 6,617 text runs per theme with 0 below AA (lowest 4.76:1 Daylight, 4.81:1 Energy, 4.82:1 Night Glow), plus desktop. Type and tap-target metrics are unchanged, and there are no console errors. The time-of-day switching passes 62 checks (boundaries, live flips, no-flash head script, persistence, backups).

Known limits: needs a real iPhone to confirm the status-bar colour per theme, the hero art's `soft-light` blend in Safari (falls back to a faded photo) and the crossfade (Safari before 16.4 switches instantly).
