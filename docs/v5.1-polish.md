# Astra Coach v5.1 — "smooth, not clunky"

Architect: Opus. Implementers: Sonnet agents. This file is the contract between them.

Goal: make Astra enjoyable, smooth and bug-free on an iPhone without changing what it does. No new features beyond what is listed. `schema` stays 4, the engine contract in `docs/v5-architecture.md` is unchanged, and every existing safety message keeps its wording.

Design skills applied (in `.claude/skills/`): `heuristic-evaluation`, `critique-typography`, `typography-scale`, `spacing-system`, `critique-information-density`, `critique-affordance`, `form-design`, `feedback-patterns`, `micro-interaction-spec`, `animation-principles`, `peak-end-rule`, `zeigarnik-effect`, `fitts-law`, `platform-conventions`, `ux-writing`, `accessibility-audit`.

## What the audit found (390 px, seeded 4-week fixture and a fresh profile)

No console errors and no `NaN`/`undefined` text. The problems are friction, density and a type system that grew by accretion:

| # | Finding | Heuristic / skill | Severity |
|---|---|---|---|
| 1 | Logging set 2 of a first-time exercise fails ("Enter valid weight and repetitions") because the weight just used in set 1 isn't carried into set 2. | Error prevention, `form-design` | P1 bug |
| 2 | Effort must be typed for every set or the set won't save. | Efficiency, `form-design` | P1 |
| 3 | Rest bar "Next: set 2 · 6" omits the weight when there's no prescription yet. | Visibility of status | P2 |
| 4 | Every training day starts with a check-in whose key question is a dropdown ("Choose an answer"), and sleep is retyped daily. | `form-design`, `fitts-law` | P1 |
| 5 | Finishing asks for after-session back discomfort from blank, then shows a toast and jumps to a long Progress page. The best moment of the session is flat. | `peak-end-rule`, `feedback-patterns` | P1 |
| 6 | Today's weight chart is scaled from current weight to goal (55 → 65 kg), so 4 weeks of data is a flat line on the floor, and the "65 kg" label overlaps the dashed line. | `data-visualization` basics, `critique-visual-hierarchy` | P2 |
| 7 | Progress lists all 20 sessions and every weigh-in: ~9,500 px of scroll. | `critique-information-density` | P2 |
| 8 | Nutrition's date control is a raw `11/02/2026` date field. | `platform-conventions`, `ux-writing` | P2 |
| 9 | Train ends in three walls of text (warm-up, comfort, engine). | `critique-information-density`, `ux-writing` | P3 |
| 10 | ~40 distinct font sizes (8–76 px) and 9 weights (400–850); text as small as 8 px; hero title up to 76 px/800. This is what reads as "clunky". | `critique-typography`, `typography-scale` | P1 |
| 11 | Spacing is ad hoc; the six-workout picker wraps into a 3×2 grid; the Train subtitle is squeezed into ~60 % width. | `spacing-system`, `platform-conventions` | P2 |
| 12 | Little tactile feedback: no press states on most rows, no haptic on set save. | `feedback-patterns`, `micro-interaction-spec` | P2 |

## Design tokens (already in `styles.css`, the `:root` block after the iOS palette)

Type, as `font` shorthands — use `font: var(--t-headline)` etc.:

| Token | Spec | Use |
|---|---|---|
| `--t-display` | 700 44/1.05 rounded | hero numbers (body weight, next target) |
| `--t-large` | 700 32/1.12 | page titles (Today, Train, Nutrition, Progress) |
| `--t-title2` | 700 22/1.2 | section headers ("This week", "Recent") |
| `--t-title3` | 600 19/1.25 | card titles, sheet titles |
| `--t-headline` | 600 17/1.3 | row titles, buttons |
| `--t-body` | 400 16/1.45 | paragraphs, inputs |
| `--t-subhead` | 400 15/1.4 | secondary row text |
| `--t-footnote` | 400 13/1.35 | meta, chips, helper text |
| `--t-caption` | 500 12/1.3 | small labels |
| `--t-caption2` | 500 11/1.25 | tab-bar labels, the absolute minimum |

Rules: only weights 400/500/600/700. Nothing below 11 px. Numbers that change (weights, timers, kcal) use `font-variant-numeric: tabular-nums`. Large titles get letter-spacing −0.5 px, title2 −0.3 px, everything else 0.

Spacing `--s1..--s7` = 4, 8, 12, 16, 20, 24, 32. Card padding `--s4` (hero `--s5`); gap between stacked cards `--s3`; section header margin `--s7` above, `--s3` below. Radii `--r-card` 22, `--r-control` 12, `--r-pill`. Motion `--ease-out`, `--ease-spring`, `--dur-press` 120 ms, `--dur-quick` 200 ms, `--dur-sheet` 300 ms.

## Part A — behaviour and markup (`app.js`, `index.html`, `sw.js`). Agent A.

New CSS for anything in Part A goes at the **end** of `styles.css`, below the marker `/* ===== v5.1 components (owned by Agent A …) ===== */`, using the tokens above. Don't edit CSS above the marker.

- **A1 Carry set values forward.** In an active session, when set *i* is saved, fill every later *unsaved* row's *empty* kg/reps (or L/R) inputs for that exercise with the values just saved. When the sheet renders, a row with no prescription value takes the last saved set of this session for that exercise. Prescription prefill (`rx.sets[i]`) still wins when it exists.
- **A2 Effort carries forward.** Sets 2+ prefill effort from the previous saved set in this session. Set 1 still needs an effort; keep the existing validation message.
- **A3 Rest bar.** "Next: set 2 · 40 kg × 6" — include kg whenever known (prescription or last saved set), never "null"/"undefined".
- **A4 One-tap check-in.** Replace the warning-symptoms `<select>` with two large radio buttons styled as a segmented control: "No new warning symptoms" / "Yes, or I'm unsure". Still required, no default. Prefill sleep from the most recent check-in. Keep all safety copy.
- **A5 Finish → celebration.** Prefill "Back discomfort after training" with the session's starting pain (`S.active.pain`). After a successful save, show a summary sheet instead of a toast and a jump to Progress: a short animated check, title ("Upper A done" or "Partial session saved"), a stats row with duration (from `startedAt` to `endedAt`), sets done / planned, and volume in kg (Σ kg × reps over done sets; for single-side lifts use the saved `reps`), then personal bests and "Next time" (compute with `sessionSummary` **before** pushing the session), and one "Done" button that goes to Today. Haptic: `navigator.vibrate?.([12,40,12])`. The animation is skipped under `prefers-reduced-motion`.
- **A6 Set-saved feedback.** On save: `navigator.vibrate?.(10)`, and the row gets a `just-done` class for ~600 ms (a quick scale/tint of the check button). The undo path stays.
- **A7 Weight chart (Today).** Y-domain = min/max of the plotted weights, padded by max(0.5 kg, 15 % of the range). Draw the dashed goal line only when the goal is inside the domain; otherwise show "Goal 65 kg" as plain text in the card. No overlapping labels. Same treatment wherever this chart helper is reused.
- **A8 Progressive disclosure on Progress.** Workout journal: newest 5 plus a "Show all (N)" button; weigh-ins: newest 7 plus "Show all"; endurance: newest 5 plus "Show all". UI state only (not saved). Header captions match ("Latest 5 of 20").
- **A9 Friendly date on Nutrition.** Show "Today", "Yesterday" or "Sat 31 Oct" in the pill; overlay the native date input transparently on the pill so a tap opens the picker. The Next arrow is disabled on today.
- **A10 Less text on Train.** Put "Before your first set" + "Comfort before intensity" into one collapsed `<details>` titled "Warm-up and safety" (wording unchanged inside). Keep "Build your engine" as a compact card with its button.
- **A11 Resume an unfinished session on Today.** If `S.active` exists, Today's hero shows "{Workout} in progress", a progress bar of sets done / planned and a primary "Resume" button. Check what exists first; only add what's missing.
- **A12 Version 5.1.0.** `VERSION` in `app.js`, every `?v=` in `index.html`, the `sw.js` shell list and cache name `astra-coach-shell-5.1.0`, and the sidebar version label.
- **A13 Bug sweep.** Run the flow script (below), fix anything broken you find, and list each fix in your report.

## Part B — visual system (`styles.css` above the marker). Agent B.

CSS only. If something needs markup, don't touch `app.js`: list it in your report.

- **B1 Type scale.** Map every `font-size`/`font-weight`/`font-family` above the marker onto the tokens. Collapse to 400/500/600/700. Remove sizes below 11 px. Page titles use `--t-large`; section headers `--t-title2` (e.g. "This week" was ~34 px); the Today hero title ("Rest", "Upper A") is at most 34 px/700 (was `clamp(52px,17vw,76px)`); hero numbers `--t-display`. One family stack (`--font`); the rounded face (`--font-num`) only for big numerals.
- **B2 Spacing.** Card padding, stacked-card gaps, section header margins and list-row padding follow the spacing rules above. Consistent radii.
- **B3 Train header.** The subtitle under "Train" spans the full content width (it currently wraps at ~60 %).
- **B4 Workout picker.** One horizontally scrolling row of pills (no wrap), scroll-snap, hidden scrollbar, ≥ 44 px tall, active pill filled. Same for any `.segmented` with more than 4 options; ≤ 4 options stay a classic segmented control.
- **B5 Exercise rows.** Thumbnail ~64 px, name `--t-headline` (2 lines max with ellipsis), target line `--t-subhead`, meta `--t-footnote`. Rows ≥ 60 px tall.
- **B6 Quick-add foods.** Denser grid: smaller icon (~30 px), name `--t-footnote`/600, protein `--t-caption`; keep 4 columns at 390 px, 3 below 360 px.
- **B7 Press states.** Buttons, rows and cards that are tappable: `transform: scale(.97)` on `:active` with `--dur-press`/`--ease-out`, release with `--dur-quick`. Every target ≥ 44 × 44 px. Merge the three `prefers-reduced-motion` blocks into one that disables transforms and animations.
- **B8 Sheets.** One surface colour from the grabber to the bottom (the header strip is a different blue today), slide-up with `--dur-sheet`/`--ease-out`, sheet title `--t-title3`.
- **B9 Contrast.** Muted text ≥ 4.5:1 on its surface (WCAG AA); check `--muted`/`--faint` uses on `--panel`.
