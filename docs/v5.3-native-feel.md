# Astra Coach v5.3 — feels native, not like a web page

Roles: one architect agent reviewed the app and wrote this; two implementer agents write the code. This file is the contract between them.

## Review findings

These come from the user's real path: a fresh profile in Auto theme, on a Lower A training day, at 08:00, 14:00 and 21:00. The steps were Today → Train → check-in → exercise sheet → save sets → finish. There were no console errors, and contrast is fine in all three themes. What separates the app from one built by a senior mobile team is behaviour and a few visible defects:

| # | Finding | Severity |
|---|---|---|
| 1 | After a set is saved, the "Set saved. Take your rest." toast covers Skip / Swap / Next exercise. The row tint, haptic and rest timer already confirm the save. | P1 |
| 2 | On a first-time lift the Effort cell shows a grey "6" placeholder that reads as an entered value next to the prefilled reps "6". | P1 |
| 3 | The previous-set label (e.g. "62.5×7") is crammed under the set number and clips. | P1 |
| 4 | Sheets show a drag handle, but swiping down does nothing. Every native sheet dismisses with a downward swipe. | P1 |
| 5 | Number keyboards have no Next / Done flow, so you tap from cell to cell, then hunt for the save button. | P2 |
| 6 | Switching tabs swaps content instantly with no transition. | P2 |
| 7 | The check-in answer buttons have unequal heights (one label wraps). | P2 |
| 8 | The sheet subtitle shows the phase in capitals ("BUILD · Squat rack…"). | P3 |

Deferred: collapsing large titles on scroll. They carry the most layout risk with the `default` status bar, and they can't be verified without Safari.

## Part A — behaviour (`app.js`, `index.html`, `sw.js`, `README.md`). Agent A.

- **A1 No toast inside a sheet for a saved set.** Keep the haptic, row tint and rest timer, and announce "Set N saved" through a visually hidden `aria-live="polite"` region. Page-level toasts (quick-add, undo and so on) are unchanged. Any other toast that fires while a sheet is open keeps the bottom placement.
- **A2 Effort placeholder.** Use "1–10" instead of a number. Keep the carry-forward behaviour.
- **A3 Previous set.** Move "last time" off the set-number cell into a small caption under that row's inputs, e.g. "Last: 62.5 × 7". Give it a clear class (`.set-prev`) for B. Leave the caption out when there's no previous value.
- **A4 Swipe down to dismiss sheets.**
  - **Where the drag works:** with Pointer Events, on the grabber strip and the sheet header area only (top ~56 px), never on scrolling content, inputs or buttons. The sheet follows the finger downward (no upward drag).
  - **On release:** dismiss when dragged more than 120 px or flicked faster than ~0.5 px/ms. Otherwise snap back.
  - **Mechanics:**
    - dismissal reuses `close()` (and whatever the ✕ does for that sheet, e.g. the celebration's Done);
    - add class `dragging` while the finger is down and `snap` while it animates back;
    - set `transform` inline only during the drag;
    - under reduced motion, keep the drag-to-dismiss but make the snap-back instant.
  - **Must not break:** taps on the ✕ button, text selection or scrolling inside the sheet.
- **A5 Keyboard flow.** Set inputs get `enterkeyhint="next"` (kg, reps, L, R) and `"done"` (effort). Enter moves to the next input in the row. On effort, Enter saves the set the way the + button does, with the same validation, then focuses the next unsaved row's first input when one exists, or blurs. Other forms get sensible `enterkeyhint` values, with Enter submitting as before.
- **A6 Tab transitions.** When a tab-bar or sidebar navigation changes the tab, render inside `document.startViewTransition` if the API exists and reduced motion is off. Otherwise render as today. Only tab changes use it, not every `render()`, and never while a sheet is open.
- **A7 Sentence case.** The sheet subtitle reads "Build phase · Squat rack with safety bars", not "BUILD ·".
- **A8 Version 5.3.0.** Bump `VERSION`, every `?v=`, the `sw.js` shell list, the cache name `astra-coach-shell-5.3.0` and the sidebar label. Add a README "New in v5.3" section.

## Part B — styles (`styles.css`). Agent B.

- **B1 Drag.**
  - `dialog.dragging`: no transition, `will-change: transform`, `touch-action: none` on the drag zone only.
  - `dialog.snap`: transform transition ≈ 250 ms `--ease-spring`.
  - Grabber hit area ≥ 44 px tall, with the visible bar unchanged.
  - The backdrop fades with the drag distance if that's feasible in CSS (e.g. A sets a `--drag` custom property); otherwise skip it.
- **B2 View transitions.** A short, calm crossfade (≈ 180 ms) on `::view-transition-old(root)` / `::view-transition-new(root)`, with a 6–8 px upward settle on the new view. The tab bar and topbar get their own `view-transition-name` so they don't fade. Off under reduced motion, in the single reduced-motion block.
- **B3 `.set-prev` caption.** `--t-caption` in `--muted`, aligned under the inputs, never clipped, in all three themes.
- **B4 Check-in choices.** Equal heights (stretch). Labels may wrap but are vertically centred.
- **B5 Polish found while verifying.** Fix anything that looks unfinished in the before/after screenshots of the hot path in all three themes. List each item.

## Acceptance

- `node --test` 86/86 and `node --check` on every JS file.
- No console errors in the three themes, with fresh and seeded profiles.
- Contrast and type/tap metrics unchanged.
- Playwright with touch emulation:
  - a pointer drag of 150 px from the grabber closes the sheet;
  - a 60 px drag snaps back;
  - a drag that starts inside the scrolling content scrolls and doesn't dismiss;
  - the ✕ still works.
- Keyboard: kg → reps → effort → Enter saves set 1 and focuses set 2's kg.
- After a set is saved, no toast covers the sheet's buttons, and the live region holds "Set 1 saved".
- With `startViewTransition` stubbed absent, tab changes still work.
- Don't commit. The architect reviews and ships after the user's go-ahead.

## Outcome

Shipped as specified, with one correction found in review: iPhone number and decimal pads have no Return key, so the A5 Enter flow (and `enterkeyhint`) only helps with hardware keyboards. The README says so.

Verified beyond the acceptance list:
- real touch input over CDP: a 220 px swipe closes; 50 px snaps back; a drag starting in the body scrolls it (`scrollTop` 0 → 84) without closing; `touchcancel` mid-drag resets;
- the `.set-prev` caption with real history in all three themes, on bench and the single-arm L/R row: never clipped, with Next exercise reachable after a save;
- Return still inserts a newline in the finish note and coach notes, does not submit the food form early, and leaves selects alone.

Still needs a real iPhone: the swipe feel, the view-transition crossfade (Safari 18+) and the status-bar colour per theme.
